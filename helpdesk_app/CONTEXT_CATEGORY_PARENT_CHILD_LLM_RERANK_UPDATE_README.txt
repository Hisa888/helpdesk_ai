# 問い合わせ精度改善アップデート

## 目的
「PCが遅い」スレッド内で「更新処理はなさそう。他に考えられますか？」と聞いた時に、
MFA更新・CRM更新など、別カテゴリのFAQへ飛ぶ問題を抑制します。

## 追加した機能

### 1. カテゴリ固定検索
- スレッド開始時の質問と採用FAQからカテゴリを推定します。
- 現在スレッドにカテゴリを保持します。
- 同一スレッド内の追加質問では、そのカテゴリに近いFAQを優先します。
- カテゴリ外FAQにはペナルティを付けます。

例：
- 「パソコンが遅い」→ PC動作遅延・性能カテゴリ
- その後の「更新処理はなさそう。他に考えられますか？」→ PC性能系FAQを優先

### 2. 親FAQ → 子FAQ
- 既存の親FAQ/子FAQ列がある場合、同一親FAQ配下の詳細FAQを優先します。
- 子FAQが未整備でも、代表的なExcelセーフモード・アドオン無効化・Office修復は同じ親回答を繰り返さず、手順回答へ誘導します。

### 3. LLM再ランキング
- TF-IDF候補の上位が接戦の時、LLMに候補FAQ番号を選ばせます。
- LLMが使えない場合は、従来順位に自動フォールバックします。
- 速度劣化を避けるため、候補差が小さい時・スレッドカテゴリがある時・補足質問時を中心に実行します。

## 主な修正ファイル
- modules/inquiry_thread_ui_runtime.py
- modules/search_runtime.py
- modules/query_flow_runtime.py

## 管理者向け補足
FAQの category 列を整備すると精度がさらに上がります。
推奨カテゴリ例：
- PC動作遅延・性能
- Office / Excel
- ネットワーク / VPN / Wi-Fi
- アカウント / ログイン / パスワード
- ディスプレイ / 画面
- プリンタ / 印刷
- メール / Outlook
- 申請書 / 書式 / 業務申請
- アプリ / ソフト導入

2. 「更新処理はなさそうです。他に考えられますか？」

期待値：MFA更新/CRM更新ではなく、PC性能系の確認候補が優先されます。
