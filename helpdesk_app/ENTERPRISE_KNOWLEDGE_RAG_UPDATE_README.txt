企業ナレッジ検索RAG改善

目的:
- 特定文書・特定語のハードコーディングではなく、社内規程/手順書/マニュアル/PDF/Word/TXT/Wiki/Excelなど、多様な文書に対応しやすい検索へ改善。

主な修正:
1. 汎用セクション分割
   - 第N条だけに依存せず、番号見出し、Markdown見出し、短い見出し、空行区切りの構造を利用して分割。
   - Wordで見出しスタイルが付いていない文書も、本文構造からセクション化。

2. 見出し重み付け検索
   - section_title / location / body を分けて保持。
   - search_textでは見出しを自然に重み付けし、質問意図に近いセクションを上位化。

3. 旧RAGデータ互換
   - 既存chunks.jsonに大きなWord/PDF/TXTチャンクが残っていても、読み込み時に汎用見出し単位へ補正。
   - 古いTF-IDF indexはchunk数/id不一致時に自動再生成。

4. 企業ナレッジ用しきい値
   - Word/PDF/TXT/WikiはFAQよりTF-IDFスコアが低く出やすいため、見出しが取得できている場合のみ knowledge_doc_rag_threshold を適用。
   - 既定値: 0.18。

5. 回答混入防止
   - Word/PDF/TXT/Wikiは上位1セクションだけを回答根拠に採用。
   - LLMが別項目を混ぜる事故を避けるため、企業ナレッジ文書はまず決定的に該当セクションを整形表示。

確認例:
- 「システム権限者はどのような事を行いますか？」
  → 「第6条 情報システム権限者」を優先表示。

注意:
- 既存のRAGデータでも補正されますが、管理画面から該当ドキュメントを再アップロードすると、より綺麗なセクションindexになります。
