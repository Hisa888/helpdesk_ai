# Safe RAG Consistency Guard Rebuild

## 目的
RAGスコアだけで最終回答を決めると、以下のような矛盾回答が発生するため、回答前の安全確認を追加しました。

- 「第13条」を聞いているのに「第6条」を回答する
- 「申請書はどれ？」に対してExcelの「○」だけを回答する
- 「説明して」に対してチェックシートの判定行だけを回答する
- 質問内容と根拠が一致しない候補を自信ありげに回答する

## 修正方針
以下の優先順位で回答します。

1. FAQ完全一致・言い換え一致
2. 条文・書式・ファイル名など明確な指定は直接検索
3. RAGスコアは候補抽出だけに使用
4. 最終回答前に質問と候補の矛盾チェック
5. 怪しい場合は回答せず候補表示
6. Groqで文章整形

## 主な修正内容

### 1. 第◯条の直接検索
質問に「第13条」「13条」などの条番号が含まれる場合、通常のRAGスコアではなく、文書内の条文構造から直接取得します。

例：
「情報システム管理規程の13条は何ですか？」
→ 情報システム管理規程案.docx / 第13条 保管場所

### 2. RAGスコアの扱い変更
RAGスコアは候補抽出には使いますが、最終回答の決定権にはしません。

### 3. 矛盾チェック追加
回答前に以下を確認します。

- 質問は第13条なのに候補が第6条ではないか
- 申請書を聞いているのに申請書名がない候補ではないか
- 説明・規程内容を聞いているのにExcel判定だけではないか

矛盾がある場合は、断定回答せず参考候補として表示します。

### 4. 安全回答
根拠が弱い場合は、無理に回答せず、以下のように安全に返します。

「社内資料内に関連しそうな候補は見つかりましたが、質問内容と根拠が完全には一致しないため、断定回答は控えます。」

## 反映後に必要な作業
古いRAG索引が残っている場合は、以下を実施してください。

1. Streamlitを再起動
2. 管理者画面で「ドキュメントRAGを初期化」
3. 情報システム管理規程案.docx、組織規程.pdf、申請書説明Excelなどを再アップロード
4. 「この内容でRAGへ反映」

## 確認質問

- 情報システム管理規程の13条は何ですか？
- マルウェア対策について教えてください
- パスワードのルールはありますか？
- 顧客の領域作成の申請書はどれですか？
